# 12 扩展：自控协议（CTDP 与 RSIP）

本章说明 Quartz 以后如何集成 edmond 在《如何提高自制力？》（知乎，2025）中提出的两代方法，以及**现在**就要在设计中预留的扩展点。协议功能本身安排在 M7（09），首版不实现。原文按其文末声明可自由使用，需注明作者。

## 1. 方法摘要

### 1.1 CTDP：链式时延协议

| 原理或机制 | 内容 |
|---|---|
| 神圣座位 | 指定一个标志（座位、帽子、一条消息）。触发后必须以最好状态完成一个专注任务（例如 60 分钟） |
| 主链 | 每完成一次记一个节点 #1、#2……；一次失败即清零，从 #1 重新开始 |
| 下必为例 | 疑似违规时只能二选一：判失败（链清零），或判允许（该行为在这条链今后的整个生命周期内永久允许） |
| 线性时延（辅助链） | 预约信号触发后，必须在 15 分钟内触发神圣座位；预约链同样受神圣座位与下必为例保护 |
| 二次预约信号 | 预约信号后 14 分 30 秒内必须发出“即时启动”信号，之后尽快开始 |
| 侦查任务 | 只需专注 5 分钟即算完成，进入状态可延长到 60 分钟；失败不影响主链 |
| 层级与兵种 | 三个 # 组成 ##，三个 ## 组成 ###……；任务单元分为突击、侦查、指挥、特勤、工程、炊事等类型，按类型组合 |
| 储君继承制 | 精锐链（只在最佳状态启用）崩溃时，状态最好的普通链继承为新的精锐链 |

### 1.2 RSIP：递归稳态迭代协议

| 机制 | 内容 |
|---|---|
| 国策（定式） | 针对“有效干预节点”的局部最优规则，例如“回家 15 分钟内洗澡”“不在沙发上用手机” |
| 国策树 | 当天做到某国策的要求，可以把它作为子节点加入树中，**每天最多加一个** |
| 递归熄灭 | 某国策被打破，熄灭它及其全部子节点；之后可以重新加入树的末梢 |
| 国策库与内化进度 | 熄灭的国策回到库中，但“已坚持天数”这一内化进度保留 |
| 国策组 | 若干国策打包为一个节点，带容错名额（如 5 个允许熄灭 1 个），组仍点亮时不影响子节点 |
| 水密隔舱 | 不可抗力时冻结指定国策的结算，到期当天必须一次性重新满足 |
| 可强化国策 | 如作息时间逐级提前，记为“强化 +N”；失败时退回 +0，不必熄灭 |
| 类型 | 被动（在某条件下不做某事、机制告示牌）、半被动（挂在必然发生的触发条件上）、主动（待办式，原文建议少用） |
| 每日结算与复盘 | 每晚结算国策是否满足；“赢麻了”记录当天的喜报并定级 |

## 2. 与 Quartz 的契合点

Quartz 已经持续记录前台应用、标题、网页、空闲与锁屏，并有分类规则、标注和托盘入口。这让它可以为两代方法提供原文中靠自觉记录的部分：

| 方法中的需求 | Quartz 能提供的 |
|---|---|
| 专注任务是否保持“最好状态” | 任务期间的前台事实；命中“疑似违规”条件时提示用户裁决 |
| 下必为例的判例 | 判例保存为条件规则，复用分类规则的条件引擎，今后自动放行同类行为 |
| 工作量证明、不可篡改 | 只追加的事件日志，节点关联到真实的前台事实 |
| 预约 15 分钟 | 核心定时器与托盘倒计时 |
| 国策“23:30 后不用限制组 App”“起床后 30 分钟不娱乐” | 在电脑上可由前台事实自动检查 |
| 每晚复盘 | 今天页已有的统计；“喜报”记录可写入标注 |

Quartz 只能观测这台电脑。手机、洗澡、洗碗这类国策只能手动结算。

## 3. 原则

1. **用户是裁判。** Quartz 只发现“疑似违规”并给出证据，判失败还是判允许永远由用户决定。Quartz 不自动清零任何链或熄灭任何国策。
2. **事件是事实，状态是派生。** 触发、完成、裁决、点亮、熄灭都作为只追加的事件存储；链长、国策树形态由事件回放得出，与 D5“存事实、查询时求值”一致。事件不修改、不删除（用户按范围删除数据时除外，见 03 第 6 节）。
3. **不打扰。** 提示只在协议进行中、有明确依据时出现，并有宽限时间。没有进行中的协议时，Quartz 的行为与首版完全相同。
4. **资源预算不变。** 协议只在进行中时设置一次性定时器，不轮询；空闲时的唤醒频率仍满足 08 第 1.1 节。
5. **隐私规则照常适用。** 证据只引用事实 ID，不复制标题；提示中的标题经 06 的隐私求值；日志不写标题。

## 4. 模块结构

```text
quartz-protocols（纯逻辑 crate，无 Windows、SQLite、GPUI 依赖）
  ├─ ctdp：链状态机、层级编号、判例匹配、预约与侦查计时规则
  └─ rsip：国策树、递归熄灭、国策组容错、冻结、强化、每日结算

quartz（核心）
  └─ selfreg 模块
       ├─ 事件存储：协议事件表与派生状态缓存（store 迁移）
       ├─ 触发入口：托盘、全局热键、--cli、界面、（以后）浏览器扩展
       ├─ 监视器：订阅采集状态，按条件检测疑似违规
       ├─ 评估器：基于查询管线的国策自动检查
       └─ IPC：focus.*、policy.* 操作与 selfreg 订阅主题

quartz-ui
  └─ 专注页（链、判例、预约倒计时）、国策树页、每日复盘
```

`quartz-protocols` 与 `quartz-domain` 一样可在任何平台测试。协议规则（例如“每天最多加一个国策”“失败熄灭子树”）全部在这里实现并单测。

## 5. 数据模型草案

M7 定稿时再写迁移；这里只确定结构，保证首版 schema 不需要为它改动。

```sql
-- 协议定义：神圣座位/链、预约链、国策、国策组
CREATE TABLE protocol_objects (
  id               INTEGER PRIMARY KEY,
  uuid             TEXT NOT NULL UNIQUE,
  kind             INTEGER NOT NULL,       -- 1 chain | 2 reservation_chain | 3 policy | 4 policy_group
  name             TEXT NOT NULL,
  config           TEXT NOT NULL,          -- JSON：任务时长、单元类型、触发标志、国策类型与评估方式、容错名额等
  parent_id        INTEGER REFERENCES protocol_objects(id), -- 国策树、链层级
  created_utc_ms   INTEGER NOT NULL,
  archived         INTEGER NOT NULL DEFAULT 0
);

-- 只追加的事件日志
CREATE TABLE protocol_events (
  id               INTEGER PRIMARY KEY,
  uuid             TEXT NOT NULL UNIQUE,   -- 客户端生成，重试幂等
  object_id        INTEGER NOT NULL REFERENCES protocol_objects(id),
  kind             INTEGER NOT NULL,       -- 见下表
  at_utc_ms        INTEGER NOT NULL,
  ref_event_id     INTEGER REFERENCES protocol_events(id), -- 裁决指向疑似违规、完成指向开始等
  payload          TEXT,                   -- JSON：目标声明、证据中的事实 ID 范围、强化等级等
  created_utc_ms   INTEGER NOT NULL
);

-- 判例不单独建表：每条链有一个 kind = precedent 的规则集（03 第 2.6 节 rule_sets.chain_id），
-- 只能追加 rule 条目。judged_allow 事件的 payload 记录新增判例的规则全名与规则集版本。
```

| 事件 `kind` | 含义 |
|---|---|
| `reservation_made` / `reservation_fulfilled` / `reservation_expired` | 预约信号、按时开始、超时（超时后需要裁决） |
| `immediate_signal` | 二次预约的即时启动信号 |
| `session_started` / `session_completed` / `session_abandoned` | 专注任务开始、完成（生成节点）、主动放弃 |
| `scout_started` / `scout_extended` | 侦查任务开始、延长为正式任务 |
| `violation_suspected` | 监视器或用户报告的疑似违规，payload 带证据范围 |
| `judged_fail` / `judged_allow` | 下必为例裁决；`judged_allow` 同时生成判例 |
| `chain_reset` / `chain_succeeded` | 链清零；储君继承 |
| `policy_lit` / `policy_extinguished` | 点亮（加入树）、熄灭（payload 带级联熄灭的子节点） |
| `policy_settled` | 每日结算结果：满足、未满足、冻结、组容错吸收 |
| `policy_frozen` / `policy_thawed` | 水密隔舱冻结与解冻 |
| `policy_upgraded` / `policy_downgraded` | 强化 +N 与退回 |
| `win_logged` | 复盘喜报 |

链长、当前节点编号、国策树的点亮状态、每个国策的内化进度（累计点亮天数）都从事件回放得到，可以缓存，缓存可随时重建。判例与国策检查都是规则集（规则格式文档 3.4、3.5 节），与其他规则一样有版本、diff 与解释；判例规则集只能追加。它们同样受 03 第 8 节的迁移与 10 第 4.1 节的文本比较规则约束。

## 6. 监视与评估

### 6.1 专注任务的疑似违规

任务进行中，监视器订阅采集线程的状态变化，按以下顺序判断：

1. 当前前台片段命中这条链的任一判例 → 放行；
2. 命中链配置中的“疑似违规条件”（默认：分类倾向为分心的分类，或锁屏、离开超过阈值） → 进入宽限期（默认 15 秒）；
3. 宽限期内回到正常 → 不提示；
4. 宽限期结束仍命中 → 写 `violation_suspected`，提示用户裁决。

用户也可以随时主动报告疑似违规（例如离开电脑去拿快递）。裁决界面给出两个按钮“判失败（链清零）”“判允许（永久判例）”。判允许时按第 8.1 节的范围阶梯预填判例，默认选最窄的一级。

### 6.2 国策的自动检查

国策的评估方式三选一：

| 方式 | 适用 | 实现 |
|---|---|---|
| 手动 | 电脑观测不到的行为（洗澡、手机） | 每日结算时用户勾选 |
| 自动 | 可由前台事实判断 | 评估器在结算时运行谓词，结果直接记为满足或未满足 |
| 自动建议 | 可观测但可能误判 | 评估器给出建议和证据，用户确认；未满足的判定同样遵循下必为例 |

谓词基于查询管线的派生片段（03 第 5 节），首批提供：

- 时间窗内，命中条件 C 的活跃时长不超过 D（例：23:30–07:00 内“限制组”App 为 0）；
- 某个锚点事件之后 N 分钟内，不出现命中条件 C 的活动（例：当天第一次活跃后 30 分钟内不出现娱乐分类）；
- 当天第一次或最后一次活跃时间早于或晚于 T（例：作息类可强化国策的检查）。

条件 C 使用分类规则的同一套字段与操作符，也可以直接引用分类（“分类 = 娱乐”）。

## 7. 现在预留的扩展点

以下改动写入首版设计，避免以后改 schema、缓存键或线程模型：

| 扩展点 | 首版设计中的位置 | 内容 |
|---|---|---|
| 逻辑日起点 | 03 第 1 节、04 `query.day` | 设置 `day.start_offset_min`（默认 0，范围 0–720）。“今天”与日统计按本地日期加偏移切分，偏移进入查询语义与日缓存键。RSIP 的每日结算使用同一个逻辑日 |
| 统一截止时间调度器 | 01 第 6 节 | 暂停、隐私模式、保持计时、空闲例外的截止时间由核心的一个调度器管理：只为最近的截止时间设一次性定时器，持久化，重启恢复。协议的预约、侦查、任务时长与结算时间以后直接注册到这里 |
| 条件引擎独立 | 03 第 2.6 节 | 规则条件的解析、规范化与匹配作为 `quartz-domain` 的独立组件，分类、隐私、以后的判例与国策评估共用 |
| 托盘菜单分区 | 07 第 1.3 节 | 菜单由若干分区组成，每个分区由一个模块提供；协议模块以后加入“预约 / 开始任务 / 侦查”分区 |
| 时间轴叠加轨 | 07 第 4 节 | 时间轴除主轨与应用泳道外，支持由查询返回的叠加轨（例如专注任务、预约区间） |
| IPC 命名空间与订阅主题 | 04 第 5、7 节 | 新模块使用独立的操作前缀（`focus.*`、`policy.*`）与订阅主题，角色权限表按前缀授权 |
| 全局热键与通知 | 09“以后” | 协议依赖全局热键（预约与即时信号）和可交互通知（裁决）。列为 M7 的前置工作 |

## 8. 交互要点

- **触发要轻。** 预约、开始、侦查在托盘左键菜单的第一屏，或用全局热键一步完成，不需要打开界面（界面冷启动可能要数秒，见 08 第 1.3 节）。
- **裁决要快。** 疑似违规用 Windows 可交互通知提示，通知上直接有两个裁决按钮；点通知正文才打开界面编辑判例。
- **计时可见。** 预约与任务倒计时显示在托盘提示与托盘图标角标上。
- **复盘集中。** 每日复盘页汇总当天节点、裁决、国策结算与喜报，结算在逻辑日结束后的第一次打开时进行，也可以手动提前。
- **语气中性。** 遵循 07 的状态行原则，失败只陈述事实，不使用惩罚性措辞。

### 8.1 规则编写

判例、国策检查与 Quartz 的其他规则使用同一种文本格式 `quartz-rules/1`，规范见 [规则格式文档](../rules/rule-format.md)。

- **Quartz 不包含任何 LLM 或 Agent 功能，也不调用任何 AI 服务。** 需要帮助时，用户把规则格式文档和“复制情况说明”（07 第 6 节）生成的文本交给自己选择的 AI，再把 AI 写出的规则粘贴回 Quartz 导入。发出什么内容完全由用户决定。
- 导入时 Quartz 严格校验，错误带路径和固定错误码，可以原样贴回给 AI 修改。
- 判例必须先看预览才能保存：预览列出这条判例在过去 30 天的任务中会放行的片段，尤其标出用户没有提到的应用或域名。
- 不使用 AI 时，裁决界面提供确定性的**范围阶梯**，从当前片段直接生成判例：

| 级别 | 生成的条件 |
|---|---|
| 1 这个标题 | `app.exe_name` 等于当前应用，且 `title.raw` 等于当前标题（标题被隐私规则丢弃时不提供此级） |
| 2 这个文档 | `app.exe_name` 等于当前应用，且 `doc.document` 等于提取出的文档 |
| 3 这个网站 | `web.domain` 后缀等于当前域名 |
| 4 这个应用 | `app.exe_name` 等于当前应用 |
| 5 这个分类 | `category` 等于当前分类 |

每一级都可以再加连续时长或累计时长上限。默认选中能覆盖当前片段的最窄一级。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 自动检测误报导致打扰，或让用户对规则失去信任 | 宽限期、判例优先、只在任务进行中检测；M7 记录误报率（09 H12） |
| 规则过多让 Quartz 变成“监工” | 协议功能默认关闭，在设置中启用；未启用时不创建任何协议数据 |
| 事件日志与事实被分别删除后引用失效 | 证据只存事实 ID 范围；事实被删除后，证据显示为“已删除”，裁决结果不变 |
| 原文方法对部分人不适用（原文第 6 节注） | 协议是可选模块，不影响 Quartz 的记录与统计功能 |
