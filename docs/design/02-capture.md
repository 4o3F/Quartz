# 02 采集

采集只产生事实，不做分类。管线如下：

```text
系统事件 ──▶ 观测（Observation）──▶ 身份解析 ──▶ 隐私策略（06）──▶ 计时状态机 ──▶ 写入命令
```

## 1. 前台与标题事件

### 1.1 事件来源

| 事件 | 机制 | 处理 |
|---|---|---|
| 前台切换 | 全局 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)` | 记录 HWND 和时间 |
| 标题变化 | 只对当前前台进程挂 `EVENT_OBJECT_NAMECHANGE`（指定 PID） | 只接受 `hwnd == 当前前台 && idObject == OBJID_WINDOW && idChild == CHILDID_SELF` |
| 最小化与恢复 | `EVENT_SYSTEM_MINIMIZESTART` / `MINIMIZEEND`（全局，成本很低） | 触发一次前台复核 |
| 窗口销毁 | 与标题 hook 同一个进程范围内的 `EVENT_OBJECT_DESTROY` | 退休对应窗口实例；当前前台被销毁时复核 |
| 活动桌面切换 | `EVENT_SYSTEM_DESKTOPSWITCH` | 立即复核可观察桌面与前台；覆盖范围需实测 |
| 低频复核 | 每 60 秒一次；解锁、恢复、hook 重建、虚拟桌面切换后立即复核 | 比较 `GetForegroundWindow()` 和标题，不一致就按变化处理，并给 `missed_event` 计数加一；与 59 秒确认点相邻时合并唤醒，复核间隔不超过 60 秒 |

所有 hook 的注册、重绑、解绑都在主线程消息循环里执行。回调立即用 `GetWindowTextW` 读取标题快照，观测携带 `dwmsEventTime`、接收 UTC 与单调时间、读取时刻、HWND 和前台代次。主线程到采集线程的队列容量为 1,024；满时置过载标志并丢弃新事件，不阻塞消息循环，缺口处理见 01 第 6 节。

跨进程 `GetWindowTextW` 读取系统缓存的窗口标题，不向目标发送 `WM_GETTEXT`，挂起的目标不会阻塞此读取（[Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw)）。M1 验证挂起目标与 Quartz 自身窗口的回调耗时。读不到的中间标题标为 `unreadable`，不使用后续标题追溯填充。

Windows 和扩展的标题上限统一为 4,096 个 UTF-16 单元；Windows 含结尾空字符的缓冲为 4,097。超过上限时保留截断部分，`title_status = truncated`。隐私求值和正则输入均使用截断后的文本；截断点之后的隐私关键词无法匹配，这是已知限制。

### 1.2 前台切换的处理

1. 主线程在前台变化时递增前台代次，立即取得标题快照。采集线程处理该快照，读取 `GetWindowThreadProcessId` 和窗口类名。
2. 解析应用身份（见第 2 节）。解析结束后再次确认这个 HWND 仍属于同一个 PID，防止窗口句柄被回收。
3. 采集线程发送带前台代次的重绑命令。主线程检查代次后解绑旧 hook、为新前台进程安装标题和销毁 hook，再补读一次标题。旧代次通知和命令丢弃。
4. 生成观测，交给隐私策略和状态机。启用依赖网页字段的规则时，浏览器标题须经 06 第 5 节的延迟机制后才能输出。

前台窗口为空时，生成"无前台"观测并结束当前区间。收到桌面切换事件后，若已离开可观察桌面，记录 `kind = no_foreground`、`no_foreground_reason = unknown_desktop`；返回后复核并恢复。UAC、Ctrl+Alt+Del 与 Windows 虚拟桌面的通知覆盖分别在 M1 实测。

### 1.3 标题变化的处理

- 新标题与当前标题相同时，忽略这次通知（去重）。
- 不同时，结束当前区间并开始新区间。**不做"稳定 N 毫秒才承认"的去抖**，短暂的标题也是事实。
- 标题变化很频繁时（播放器进度、终端命令、下载百分比），数据库写入按 03 第 4.2 节合并为事务，展示层按提取后的文档身份合并。原始区间照样保留。
- 同一窗口实例 10 秒内标题变化超过 50 次时，记为"标题风暴"。每个已观测到的不同标题仍切段，风暴只影响写入批量。采集线程或队列过载时记录 `capture_gaps`，不以最后标题填补缺口。

## 2. 窗口与应用身份

### 2.1 应用身份

| 情况 | 解析方法 | 身份键 |
|---|---|---|
| 普通 Win32 | `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → `QueryFullProcessImageNameW` | `exe:<规范化小写完整路径>` |
| 打包应用 | 先 `GetApplicationUserModelId`，有 AUMID 时优先使用 | `aumid:<AUMID>` |
| `ApplicationFrameHost.exe` | 枚举子窗口，找出属于其他进程、可见的 `Windows.UI.Core.CoreWindow`，再按上一行解析 | 内容进程的 AUMID |
| 提权或受保护进程 | 有限查询权限通常足够；失败时记录 `unresolved`，保留窗口类名和 PID | `unresolved:<类名>` |

- 显示名优先取 exe 版本信息里的 `FileDescription`，没有时用文件名。显示名在首次发现应用时读取一次，存到 `applications` 表。多语言版本信息的选择与 Windows 显示语言变化后的重新解析见 10 第 5 节。
- 进程元数据按 `(PID, 进程创建时间)` 缓存，进程退出后清除。有了创建时间，PID 被复用也不会混淆。
- 图标不在采集路径里提取。界面请求某个应用的图标时，核心才提取，并缓存到 `icons\<app_id>.png`。

### 2.2 窗口实例

窗口实例是 `(run_id, HWND, PID, 进程创建时间, generation)`。首次看到时分配 `window_instance_id`；进程创建时间读取失败时允许为 NULL。

观察到 `EVENT_OBJECT_DESTROY` 就退休对应实例；同一 HWND 再次出现且之前已退休，或窗口类名与此前不同，则增加 `generation` 并新建实例。销毁 hook 只覆盖当前前台进程；后台进程内同类窗口复用 HWND 仍可能未被识别，这是首版残余风险。

- 两个标题完全相同的窗口，HWND 不同，所以是不同的实例。用户决策 4 要求区分同一程序的不同窗口，靠的就是这一层。
- HWND 只在一次运行内有意义，所以带上 `run_id`。跨运行合并同一个窗口不在范围内。
- 一个浏览器窗口切换标签时，HWND 不变，标题变了：实例相同，切出新区间。

### 2.3 文档和项目身份

文档身份是从原始标题提取出来的派生数据，不在采集时计算，见 [03-data-model.md](03-data-model.md) 第 5 节。

## 3. 空闲与可用状态

可用状态和前台事实分开记录。**输入空闲时继续记录前台事实**。报表用可用状态裁剪有效时长，用户事后把一段空闲标为"在看书"时，还能看到当时开着什么窗口。

| 原因 | 检测 | 是否停止采集前台事实 |
|---|---|---|
| `idle`（输入空闲） | `GetLastInputInfo` 自适应检查 | 否 |
| `locked`（锁屏） | `WTSRegisterSessionNotification`：`WTS_SESSION_LOCK` / `UNLOCK` | 是 |
| `disconnected`（会话断开） | `WTS_CONSOLE_DISCONNECT`、`WTS_REMOTE_DISCONNECT` | 是 |
| `suspended`（睡眠） | 隐藏顶层窗口 + `RegisterSuspendResumeNotification`：`PBT_APMSUSPEND` / `PBT_APMRESUMEAUTOMATIC` | 是 |
| `paused`（用户暂停） | 托盘菜单或界面 | 是 |
| `core_offline`（核心未运行） | 不写记录；查询时把两次运行之间的空白视为这种原因 | — |

停止原因维护为集合：`locked`、`disconnected`、`suspended`、`paused`。每个通知只增删自己的原因；只有集合为空且已复核前台后，才开始新区间。`WTS_CONSOLE_CONNECT`、`WTS_REMOTE_CONNECT` 只清除 `disconnected`，不会清除锁屏或暂停。

启动时用 `WTSQuerySessionInformation` 查询锁定与连接状态，完成复核后才开前台区间。会话通知注册失败时显示异常并重试，期间保持停止。

### 3.1 空闲检测

- 默认阈值 3 分钟，可设置。
- 活跃时，在"最后输入时间 + 阈值"到期时检查一次。到期时发现有新输入，就把检查推迟到新的到期时间。所以持续操作时，大约每 3 分钟才唤醒一次。
- 已空闲时，每 5 秒检查一次是否恢复输入。恢复识别的延迟最多约 5 秒。
- 空闲区间的起点为"最后输入时间 + 阈值"，也就是说阈值以内的无操作时间仍算有效活动。和 ActivityWatch 回溯扣除整段无操作的口径不同，这一点写进统计策略版本。
- 每条空闲记录保存最后输入时间、检测时间、当时的阈值和策略版本，以便日后解释。
- `GetLastInputInfo` 的 tick 是 32 位，约 49.7 天回绕一次。实现时用 `GetTickCount64` 的低 32 位求差，并处理 API 失败和返回值异常（比如最后输入时间晚于当前时间）。

### 3.2 空闲例外

| 例外 | 首版 | 说明 |
|---|---|---|
| 临时保持计时 | 有 | 托盘菜单"保持计时 30 分钟 / 1 小时"，期间不进入空闲 |
| 应用豁免 | 有 | 指定应用在前台时不进入空闲，单次最长 2 小时 |
| 浏览器标签正在播放声音 | 有 | 来自扩展的 `audible`，只在该浏览器在前台时生效，单次最长 2 小时 |
| 前台应用音频会话 | 暂缓 | 需要 COM 和额外线程，后续按应用启用 |
| 全屏 | 暂缓 | 只作为辅助信号 |

已有空闲记录因例外提前结束时写明 `exception`。阻止进入空闲的限时例外与截止时间保存在 `settings`，到期按 `policy_changed` 复核。

## 4. 计时状态机

### 4.1 状态

```text
            ┌──────────── 可用状态解除 ────────────┐
            ▼                                       │
  ┌──▶ Tracking(区间) ──可用状态出现（锁屏/睡眠/暂停/断开）──▶ Stopped(原因集合)
  │        │
  │        └── 前台或标题变化 ──▶ 结束旧区间、开始新区间（同一事务）
  │
  └── NoForeground ◀── 前台窗口为空
```

输入空闲不改变这个状态机，只写可用状态记录。规则修改、隐私模式启停、空闲例外到期、保持计时到期都产生 `policy_changed` 边界：同一事务关闭当前区间（如有）、重新求值，停止原因集合为空时才开新区间，同时刷新 `state` 与托盘。限时状态与截止 UTC 保存在 `settings`，重启时按截止时间恢复。

### 4.2 区间边界

- 所有持久时间为 UTC 毫秒整数，区间为 `[start, end)`。
- 时长用单调时钟（`QueryUnbiasedInterruptTime`，不含睡眠时间）计算，UTC 只用来定位。
- 区间结束时，写入 `end_utc_ms` 和 `end_reason`：`switch`、`title`、`no_foreground`、`locked`、`suspended`、`paused`、`disconnected`、`shutdown`、`crash_recovered`、`clock_jump`、`midnight_split`、`policy_changed`、`capture_gap`。
- 前台区间与可用状态都在 UTC 午夜拆分，单行最长 24 小时，这样范围查询可以用"开始时间 ≥ 查询起点 − 24 小时"缩小扫描范围。前台拆分出的区间共享同一个 `session_key`。可用状态在结束时一次写出跨午夜的多行；睡眠恢复时同样补拆，读取尚未拆分的开放状态时按完整相交条件查询。

### 4.3 确认点

- 确认点周期为 60 秒减去批量等待上限 1 秒，即 59 秒；为队列延迟设置提交期限。一个事务同时推进前台、可用状态、网页开放行和运行的 `confirmed_utc_ms`，前台与可用状态还推进 `confirmed_mono_ms`。行结束时确认点列置 NULL（03 第 1 节）。正常写入时最坏丢失不超过 60 秒；无法按期确认的范围按采集缺口处理。
- 锁屏、睡眠、暂停、正常退出时立即结算。
- 核心崩溃后，前台、可用状态、网页开放行和运行都关闭到各自最后确认点，`end_reason = crash_recovered`，同时关闭旧时钟段（03 第 4.3 节）。

## 5. 时钟与运行

- 每次核心启动是一次采集运行（`capture_runs`），记录设备 ID、Windows 会话 ID、启动和结束时间。
- 每次运行内，UTC 与单调时钟的对应关系是一个时钟段（`clock_segments`）。以下情况结束当前时钟段并开始新的：
  - 收到 `WM_TIMECHANGE`；
  - 睡眠恢复；
  - 每次复核时发现"UTC 变化量 − 单调时钟变化量"的绝对值超过 2 秒。
- 前台与可用状态保存 `start_mono_ms`、`confirmed_mono_ms`、`end_mono_ms`。时钟跳变时，旧区间终点使用旧段 UTC 锚点加单调增量，保证结束不早于开始，`end_reason = clock_jump`；新 UTC 仅作新时钟段锚点。仍有效的可用状态在新段重开。
- 睡眠时间不在 `QueryUnbiasedInterruptTime` 中；恢复时以恢复 UTC 定位 `suspended` 范围，补拆午夜，并开始新时钟段。
- 系统时间回拨后，新区间可能和旧区间在 UTC 上重叠。查询按 `(run_id, sequence)` 保留先后顺序，同一时钟段内求交；跨时钟段的重叠在时间轴上标为"时钟异常"，统计按各区间的实际长度累计，UTC 裁剪只在同一时钟段内进行。标注只用 UTC，重复的墙上时间会作用于所有重复段，这是已知限制。
- 时区变化只影响日、周报表的边界，存储不变。

## 6. 验收场景

M1 的采集验收覆盖以下场景，用"人工操作脚本 + 自动断言"的方式对照：

- 快速 Alt-Tab（间隔 < 200 ms）、任务栏切换、多显示器之间切换、虚拟桌面切换
- 同一程序两个相同标题的窗口互相切换
- 浏览器切标签、播放器标题每秒变化、终端运行命令
- UWP 应用、提权应用、UAC 提示、安全桌面（Ctrl+Alt+Del）
- 锁屏、睡眠（S0 现代待机）、远程桌面断开和重连
- 修改系统时间、跨午夜、空闲阈值边界
- 运行中强制结束核心，再重启；长时间锁屏时崩溃、确认点与批量等待叠加
- 暂停叠加锁屏、睡眠叠加断开；启动时已锁定或断开，会话通知注册失败后重试
- 主线程队列过载、采集到数据库队列满、数据库写入失败与恢复；核对缺口范围
- 挂起目标进程时读取标题；超长标题、4096 UTF-16 单元边界和截断后的隐私求值

通过条件：

- 前台切换时刻误差 P95 < 100 ms；
- 时长守恒：前台与无前台事实，加停止原因的时间并集共同覆盖运行时间，无重叠、无负时长；过载范围以 `capture_gaps` 填入覆盖检查。idle 作为独立掩码检查。回拨的覆盖按运行与时钟段顺序检查；
- 低频复核发现的漏检事件（`missed_event`）每小时不超过 1 次。
