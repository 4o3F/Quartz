# 10 国际化

国际化涉及三类问题：

1. **界面语言**：界面、托盘、通知、扩展里的文字。
2. **区域格式**：日期、时间、时长、数字、一周起始日、排序。
3. **多语言数据**：窗口标题、应用名、域名本身就是任意语言。规则匹配、隐私识别、文档提取和搜索都要对它们正确工作，并且不随界面语言改变结果。

基本原则：

- **数据库与协议不存界面文字。** 内置名称、标签、错误都以键或编码存储和传输，显示时才翻译。用户自己输入的名称原样保存。
- **匹配结果与界面语言无关。** 同一份事实和规则，在中文界面和英文界面下必须得到相同的分类、隐私判决与时长。
- **原始文本不改写。** 标题、应用名按采集到的样子入库。规范化只用于比较，结果放在内存缓存里。

## 1. 语言与区域设置

首版提供 `zh-CN` 与 `en` 两种界面语言，`en` 作为回退语言。其他语言通过增加翻译文件加入，不需要改代码。

| 设置 | 默认 | 说明 |
|---|---|---|
| `ui.language` | `auto` | `auto` 时按 `GetUserPreferredUILanguages` 的顺序匹配已提供的语言。`zh-*` 匹配 `zh-CN`，其他回退 `en` |
| `ui.hour_cycle` | `auto` | `auto` 跟随 Windows 区域设置的时间格式（`LOCALE_STIMEFORMAT`），可选 12 或 24 小时 |
| `ui.first_day_of_week` | `auto` | `auto` 跟随 Windows 区域设置（`LOCALE_IFIRSTDAYOFWEEK`），影响本周页与日历 |

界面语言与区域格式分开取：系统语言是英文、区域是中国的用户，界面用英文，一周仍从周一开始。

设置保存在 `settings`。修改语言后，核心立即切换托盘文字，通过 `state` 推送新语言，界面在下一帧切换，不需要重启。

## 2. 翻译资源

### 2.1 库与组织

- 使用 `rust-i18n`。gpui-kit 依赖的 gpui-component 也用它（`rust_i18n::i18n!("locales", fallback = "en")`），二者共享一个全局语言设置。切换语言时同时调用 `rust_i18n::set_locale` 和 `gpui_component::set_locale`，组件自带的文字（日历星期、按钮）随之切换。
- 新增 crate `quartz-i18n`，放翻译文件、语言协商、复数选择与时长、日期格式化函数。核心（托盘、通知）与界面都依赖它；它不依赖 GPUI。
- 翻译文件为 `crates/quartz-i18n/locales/*.yml`，格式与 gpui-component 相同（每个键下按语言列出译文）。字符串编译进 exe，运行时不读文件。
- 键按功能分组：`tray.*`、`today.*`、`timeline.*`、`rules.*`、`settings.*`、`category.builtin.*`、`privacy.label.*`、`error.*`、`duration.*`。

### 2.2 复数与占位符

- `rust-i18n` 不处理复数。需要复数的文字写成 `.one`、`.other` 等子键，由 `quartz-i18n` 用 `icu_plurals` 按当前语言选择。中文只用 `.other`。
- 占位符用命名参数（`%{count}`、`%{app}`），不用位置参数，便于译文调整语序。
- 不拼接句子片段。“应用名 + 已 + 时长”这类句子作为一个整体的键，带占位符。

### 2.3 检查

- 测试检查每个键在所有提供的语言里都存在，且各语言的占位符集合相同。
- 托盘提示受 `NOTIFYICONDATAW.szTip` 128 个 UTF-16 单元限制，托盘相关键在测试中按最长占位值检查长度。
- 调试构建提供伪语言 `en-XA`：译文加长约 40%、加上首尾标记。用它截图检查截断、固定宽度和漏翻译的硬编码文字。

## 3. 存储与协议中的文字

| 数据 | 存储 | 显示 |
|---|---|---|
| 内置分类名 | `categories.builtin_key`，`name` 为 NULL | 翻译 `category.builtin.<key>`；用户改名后 `name` 存用户输入，不再翻译 |
| 用户分类名、规则标签、标注文字 | 原样文本 | 原样显示 |
| 隐私标签快照 | 内置规则存 `privacy_label_key`（如 `privacy.label.private_window`）；用户规则存 `privacy_label` 文本 | 有键时按当前语言翻译，否则显示文本 |
| 枚举（结束原因、停止原因等） | 整数编码（03 第 2.9 节） | 界面按编码翻译；`enum_labels` 只供开发排查，保持英文 |
| 错误 | 协议错误码（01 第 7.1 节） | 界面按错误码翻译；日志与命令行输出用英文 |
| 应用显示名 | 采集时取得的文本（见第 5 节） | 原样显示 |

协议只传键、编码、数字与原始数据，不传已翻译的句子。唯一的例外是核心自己显示的托盘和通知文字，由核心用 `quartz-i18n` 按当前语言生成。

界面语言变化不影响查询结果与缓存键：派生片段和聚合只引用 ID 和编码，名称在界面渲染时才解析。托盘摘要在语言变化时重新生成。

## 4. 匹配与过滤

规则匹配、隐私规则、规则预览、未分类队列的搜索都在核心执行，使用同一套文本比较规则。

### 4.1 比较规则

| 条件 | 比较方式 |
|---|---|
| `case_sensitive = true` | 两侧先做 NFC 规范化，再按码点比较 |
| `case_sensitive = false`（默认） | 两侧先做 NFKC 规范化，再做 Unicode 默认大小写折叠（full case folding），再做 NFKC。全角与半角字母数字（`ＡＢＣ`、`ABC`）、兼容字符、大小写都视为相同 |
| `regex` | 正则匹配 NFC 规范化后的原文。是否忽略大小写由正则自身的 `(?i)` 决定（`regex` crate 的 Unicode 简单大小写折叠），与上一行的折叠方式略有差异，规则编辑器中注明 |
| `domain_suffix`、`web.domain` | 用户输入的 Unicode 域名在保存时转为 punycode（IDNA），与入库的域名比较 |

- 大小写折叠不按语言特化（例如不做土耳其语的 `I`/`ı` 特例），保证结果与界面语言无关。
- 规范化与折叠用 ICU4X 的 `icu_normalizer` 与 `icu_casemap`（编译期数据）。M1 测量它们对核心体积和内存的影响（09 H10）。
- 标题的规范化结果按 `title_id` 存在提取缓存中，不入库。规则值在规则加载时规范化一次。
- `contains`、`starts_with`、`ends_with` 在规范化后的文本上按码点序列比较。中文、日文等不分词的文字不需要分词即可匹配子串。

### 4.2 内置识别与提取规则的多语言样本

浏览器、Office 等应用的标题随**它们自己的**界面语言变化，与 Quartz 的界面语言无关。例如 Firefox 无痕窗口标题在中文版和英文版中不同，Office 的“兼容模式”后缀也随语言变化。

- 内置隐私规则（06 第 3.3 节）与内置提取规则的每个模式都列出各语言变体，全部同时生效，不按 Quartz 界面语言筛选。
- 规则数据中每个变体标注语言和是否有样本验证。M1 至少验证 `zh-CN` 与 `en` 两种浏览器语言；未验证的变体在设置页标为未验证。
- 标题模式无法覆盖的语言或浏览器，接入扩展后以扩展关联为准，未接入时记为已知缺口并在设置页提示（06 第 3.4 节）。

### 4.3 排序与搜索

- 界面里按名称排序的列表（应用、分类、规则）使用 `icu_collator` 按当前界面语言排序，中文按拼音。排行默认按时长排序，不受影响。
- 搜索框输入使用第 4.1 节的不区分大小写比较，由核心执行。

## 5. 应用显示名

- exe 的 `FileDescription` 可能有多种语言版本。读取 `\VarFileInfo\Translation` 后，按 Windows 显示语言、`en-US`、第一个可用版本的顺序选择。
- AUMID 应用在采集路径中读取已解析进程 exe 的 `FileDescription`；`ApplicationFrameHost.exe` 优先使用内容进程的版本信息。仅取得 frame AUMID 时复用同一身份键的名称缓存，未命中则以 AUMID 占位，不使用窗口标题，也不覆盖已保存的 exe 和显示名（02 第 2.1 节）。
- Windows 显示语言变化后，核心在下次启动时重新解析已知应用的显示名。名称有变化时更新 `applications.display_name` 并推进 `metadata_version`（03 第 2.7 节）。历史事实只引用 `app_id`，不受影响。
- 用户可以在界面里为应用设置自定义显示名，优先于系统名称。

## 6. 界面显示

### 6.1 格式

- 时长：`quartz-i18n` 提供短格式（托盘、柱状图标签，如 `1h 5m`、`1 小时 5 分`）和长格式（详情侧栏）。
- 日期与时间：按语言的模式键格式化（如 `M月d日 EEE`、`EEE, MMM d`），12 或 24 小时按第 1 节设置。日历计算用 01 第 7 节选定的日期库，日界按本地时区（03 第 1 节）。
- 百分比与数字使用 `icu_decimal` 按语言格式化。

### 6.2 字体

- 界面字体按语言设置回退链：基础字体 `Segoe UI Variable`；`zh-CN` 接 `Microsoft YaHei UI`；以后加入繁体中文用 `Microsoft JhengHei UI`，日文用 `Yu Gothic UI`。按语言选择 CJK 字体，避免同一汉字用错地区的字形。
- 标题、应用名可能包含任何文字，依靠 DirectWrite 的系统字体回退显示。
- 替换 07 第 3 节固定使用 “Microsoft YaHei UI” 的做法。

### 6.3 布局

- 不使用固定宽度放文字。按钮、标签、表头随文字长度伸缩；列宽不足时截断并显示完整文字的悬停提示。
- 截断按字素簇（`unicode-segmentation`），不切开组合字符与 emoji。长标题在中间省略，保留开头与结尾（结尾常是应用名或文件扩展名）。
- 从右到左的界面语言首版不支持。标题中的阿拉伯文、希伯来文按 GPUI 的文本排版显示，可能顺序不正确，作为已知限制。

### 6.4 浏览器扩展

扩展使用浏览器的 `_locales/<语言>/messages.json`，`default_locale` 为 `en`，提供 `en` 与 `zh_CN`。扩展本身文字很少（选项页与连接状态）。

## 7. 测试

- 匹配：全角与半角、大小写、NFC 与 NFD、兼容字符、中文子串、IDN 域名各有用例；同一组规则在 `zh-CN` 与 `en` 界面下结果相同。
- 内置识别：中文与英文浏览器的无痕窗口样本，中文与英文 Office 标题样本。
- 翻译：键完整性、占位符一致性、托盘长度。
- 界面：每次界面截图评审同时提供 `zh-CN`、`en` 与 `en-XA` 三套截图。
- 语言切换：运行中切换语言，托盘、界面、组件文字立即变化，查询结果不变。
