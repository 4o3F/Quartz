# M2 人工验收手册（F1）

依据 [04 IPC 第 9 节](../design/04-ipc.md#9-测试)、[07 托盘](../design/07-ui.md#1-托盘核心进程win32-原生) 和 [09 M2](../design/09-milestones.md#m2-ipc-与托盘) 执行。每节完成后在 [测量记录](../measurements.md) 追加日期、HEAD、Windows 版本、操作起止时间、命令与结果；人工项记录实际观察，未执行项写明待测。

## 1. 准备与独立目录

前置条件：Windows 桌面会话、Deno 2.9.8、仓库指定 Rust 工具链。先从托盘退出已安装的 Quartz，确认进程结束；管道名 `\\.\pipe\Quartz.<SID>.v1` 按用户固定，核心互斥量按用户和会话固定，更换数据目录不会隔离它们。以下命令全程在同一 Windows PowerShell 执行。quartz.exe 使用 GUI 子系统，命令行调用通过显式管道等待进程结束并取得退出码；导出时使用 ForEach-Object 原样传递 JSON Lines。

```powershell
Set-Location D:\Documents\403F\Quartz
git rev-parse HEAD
cargo.exe build --release -p quartz --target-dir target/windows
if ($LASTEXITCODE -ne 0) { throw 'release build failed' }
$exe = (Resolve-Path .\target\windows\release\quartz.exe).Path
$acceptanceParent = Join-Path $PWD ('target\windows\acceptance-m2-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $acceptanceParent | Out-Null
$previousLocalAppData = $env:LOCALAPPDATA
$env:LOCALAPPDATA = $acceptanceParent
$dataRoot = Join-Path $acceptanceParent 'Quartz'
$utf8 = [System.Text.UTF8Encoding]::new($false)
$core = Start-Process -FilePath $exe -PassThru
$core.Id
```

预期：仅出现托盘图标和隐藏消息窗口，数据与 `logs\core.log` 位于 `$dataRoot`。使用新目录的默认设置（日开始偏移为 0），先完成第 4 节的无标注摘要比较，再做第 5 节的快速标注。记录构建结果、独立目录、核心 PID、系统时区和本地日期。

## 2. 状态与非 Quartz 客户端拒绝

```powershell
& $exe status | Out-Host
if ($LASTEXITCODE -ne 0) { throw 'status failed' }
deno task acceptance-reject --data-root $dataRoot
if ($LASTEXITCODE -ne 0) { throw 'non-Quartz rejection failed' }
& $exe status | Out-Host
if ($LASTEXITCODE -ne 0) { throw 'core stopped serving status' }
```

预期：`status` 通过管道返回核心状态；[拒绝脚本](../../scripts/acceptance-reject.ps1) 在 PowerShell 进程中用 `System.IO.Pipes.NamedPipeClientStream` 连接当前 SID 的管道，不发送 hello，五秒内读到 EOF 或 Windows 管道关闭错误，收不到任何回复。脚本同时检查本次连接后新增的核心日志，必须有同一 PowerShell PID、`rejected pipe client` 和 `peer executable is not allowed`，仅输出该拒绝条目。记录两次 status 的结果、脚本 PASS、PID 和拒绝原因，不记录窗口标题。

其他用户与其他会话由人工验证，需要第二个账户或第二个登录会话。在该环境使用 `NamedPipeClientStream` 连接第一会话记录的 SID 管道；其他用户应被 DACL 或用户检查拒绝，同一用户的其他会话应被会话检查拒绝。DACL 拒绝可能发生在核心取得连接之前；已接受后拒绝的连接应有 PID 与原因日志。记录账户关系、会话 ID、访问拒绝或无回复断开的结果、可取得的日志。host 的扩展 ID、`data.delete`、Edge 直接启动及 cmd 中转留在 M5。

## 3. 托盘操作

每项操作前后运行 `& $exe status | Out-Host`，记录操作时间、状态、菜单和提示文字的观察；标题只记录“可见/隐藏”，不要复制实际标题。

| 操作 | 预期结果 | 测量记录 |
|---|---|---|
| 悬停、右键；活动后再看摘要 | 正常图标；提示包含今日活动时长、专注/分心占比、当前应用与持续分钟。摘要更新后重新打开菜单读取 | 提示各行是否存在、刷新时间 |
| 检查菜单 | 今日/分类/最近一小时为置灰信息；“打开 Quartz”为默认项；有暂停、保持计时、隐私模式、浏览器扩展（M5 前为 0）、设置、退出 | 项目、子菜单和可用状态 |
| 暂停 → 15 分钟，随后暂停 → 恢复 | 灰色图标；提示有自动恢复时间；status 含暂停期限；恢复后清除暂停。另一次保持暂停满 15 分钟检查自动恢复 | 两次切换与实际自动恢复时间 |
| 保持计时 → 30 分钟，连续无输入超过默认空闲阈值 3 分钟 | status 含期限；期限内不进入 idle，持续记录；锁屏仍停止。等待期限结束，或退出后换新独立目录再做空闲场景 | 授权期限、无输入时长、idle 状态、结束方式 |
| 隐私模式 → 15 分钟，切换窗口后再关闭 | 图标有隐私标记；当前提示隐藏标题，status 的前台 title 为空；关闭后后续允许的窗口事实恢复标题显示。离线导出的隐私区间是 title_hidden 且无 title | 启停时间、标题隐藏检查、离线 privacy 断言 |
| 锁屏再解锁 | 停止期间按停止状态显示；解锁复核后恢复 | 图标与状态变化 |

异常图标的数据库失败与 hook 失败选择由自动测试覆盖；不要为本轮托盘观察损坏数据库。`real_threads_recover_gate_checkpoint_report_failure_and_flush_shutdown`、`snapshots_follow_capture_and_persistence_with_fixed_priority` 与 `timed_tray_mapping_prioritizes_warning_then_grey_then_privacy` 覆盖这些分支。

语言设置必须由 UI 角色发送 `settings.set`，当前“设置…”打开的 M2 界面尚无设置控件，也没有设置 CLI。现有内存测试客户端位于 [core/app/tests.rs](../../crates/quartz/src/core/app/tests.rs)，只在测试构建中连接假端口。语言切换在 M3 UI 完成前使用以下自动测试，验证提交后通知托盘、发布新语言、恢复自动语言及拒绝 CLI 写设置；两种语言的本地菜单和提示由原生菜单与文本测试覆盖。

```powershell
cargo.exe test -p quartz --all-features --target-dir target/windows settings_ipc_commits_before_reply_and_updates_tray_and_state_through_ui_port
cargo.exe test -p quartz --all-features --target-dir target/windows native_submenus_follow_active_snapshot_and_selected_language
cargo.exe test -p quartz --all-features --target-dir target/windows tooltip_localizes_summary_foreground_elapsed_and_hidden_fields
```

预期：三条命令均通过。记录命令、结果和“M3 待补实机语言切换观察”。

## 4. 今日托盘摘要与 dump

在当天尚未创建任何标注时执行。`dump` 不包含标注表，因此 `--no-annotations` 是操作者对新验收目录的前置条件确认。默认内置分类只影响分类与专注比例，本节只比较活动时长。

在恢复记录的状态下悬停，等待摘要刷新，再次悬停读取普通提示中的“今日 Xh Ym”，立即执行下列命令。提示和 dump 不是同一次快照；若采样恰好跨过整分钟边界，重新悬停、导出并比较。

```powershell
$today = Get-Date -Format 'yyyy-MM-dd'
$summaryDump = Join-Path $acceptanceParent 'summary.jsonl'
$summaryLines = @(& $exe dump --date $today --format json | ForEach-Object { $_ })
if ($LASTEXITCODE -ne 0) { throw 'live dump failed' }
[System.IO.File]::WriteAllLines($summaryDump, $summaryLines, $utf8)
deno task acceptance-summary $summaryDump --date $today --no-annotations
if ($LASTEXITCODE -ne 0) { throw 'summary calculation failed' }
```

[计算脚本](../../scripts/acceptance-summary.ts) 复用 dump 解析，按当前 Windows 时区的本地午夜至下一午夜裁剪；逐个时钟段按事实边界切片，重叠前台取最大事实 ID，每片只计一次。只有 full/title_hidden 的窗口、且没有 idle、停止原因或 capture_gap 时计活动。NoForeground、Excluded、核心离线范围不计；回拨后的重复 UTC 在各自时钟段分别计时。开放事实仅计到各自确认点，按事实单调时长对裁剪端点做整数插值，与查询管线一致。

预期：脚本的 `active_ms` 先向下取整为总分钟，再拆为小时和分钟，与提示相同；界面可能省略为零的小时或分钟。先等摘要刷新完成；如导出时有 `stale_cursor`，重新导出整日。记录本地日期/时区、无标注前置条件、采样时间、提示小时/分钟、active_ms 和比较结果，不引用本地临时文件作为报告证据。

## 5. 空闲结束后的快速标注

先确保保持计时期限已经结束；需要立即开始时，正常退出后按第 1 节换一个新独立目录启动。保持一个允许采集的窗口在前台，从最后一次输入起无操作至少 18 分钟：默认前三分钟未进入 idle，之后需要至少 15 分钟完整 idle。移动鼠标恢复，十分钟内打开菜单。

```powershell
& $exe status | Out-Host
cargo.exe test -p quartz --all-features --target-dir target/windows prompt_obeys_idle_threshold_window_and_successful_choice
cargo.exe test -p quartz --all-features --target-dir target/windows choices_preserve_range_identity_and_exact_storage_mapping
```

预期：菜单出现“把刚才的 N 分钟记为”，包含休息、会议、阅读思考、忽略；选择一项后成功隐藏。休息写 note，会议/阅读思考写对应分类的 offline_activity，忽略写 dismissed_away。两项自动测试检查阈值、显示窗口、成功隐藏和存储映射。记录最后输入、恢复与选择时间、N、选择项、菜单隐藏结果及测试结果。

## 6. 十分钟慢客户端

本节使用临时数据库、假平台端口、真实采集/数据库线程及随机名称的真实测试管道，不需要第 1 节的核心运行。单独串行运行，避免同一测试进程的其他测试干扰 Private Bytes。

```powershell
cargo.exe test -p quartz --all-features --target-dir target/windows platform::windows::ipc::tests::slow_client_ten_minutes_preserves_capture_commits_status_budget_and_private_bytes -- --ignored --exact --nocapture --test-threads=1
```

预期：UI 订阅 state 后停止读取至少 600 秒，驱动持续发布大状态并提交采集暂停/恢复写入。每个提交通过独立 SQLite 读取确认新行；nearest-rank P95 < 1 秒；状态发布 < 100 ms，另一个客户端每次 core.status < 500 ms；连接保持存在，排队字节及峰值 ≤ SEND_BUFFER_LIMIT（1 MiB）。每轮采样 `PROCESS_MEMORY_COUNTERS_EX.PrivateUsage`，相对连接及工作线程已启动的基线增量 ≤ 1 MiB + 32 MiB；32 MiB 留给两个各 2 MiB 的存储缓存、检查连接缓存、工作线程与运行时、状态编码、测试延迟样本和分配器保留空间。报告包含运行时长、提交数、P95、排队峰值、Private Bytes 基线/峰值/增量及上限。

记录完整命令、PASS/FAIL 及报告中的数值。普通工作区测试会自动运行同一驱动的两秒版本；它用独立测试进程测量内存，以隔离并行测试的分配。F1 交付时只编译十分钟版本，长测由人工执行。

## 7. 正常退出与离线不变量

从托盘“退出 Quartz”，再运行以下命令；跨午夜或改过时间时，`$dates` 应包含本次所有运行访问过的日期。导出方法沿用 [M1 第 2 节](m1.md#2-每个场景的导出与自动断言)。

```powershell
if (-not $core.WaitForExit(10000)) { throw 'core did not exit normally' }
$dates = @((Get-Date -Format 'yyyy-MM-dd'))
$lines = [System.Collections.Generic.List[string]]::new()
foreach ($day in $dates) {
    $part = @(& $exe dump --offline --date $day --format json | ForEach-Object { $_ })
    if ($LASTEXITCODE -ne 0) { throw ('offline dump failed: ' + $day) }
    foreach ($line in $part) { $lines.Add($line) }
}
$offlineDump = Join-Path $acceptanceParent 'offline.jsonl'
[System.IO.File]::WriteAllLines($offlineDump, $lines, $utf8)
deno task acceptance $offlineDump
if ($LASTEXITCODE -ne 0) { throw 'offline invariants failed' }
$env:LOCALAPPDATA = $previousLocalAppData
```

预期：退出完成，离线 dump 成功，format、coverage、idle、midnight、recovery、privacy、clock 全部 PASS；本轮正常退出的运行以 user_exit 结束，时钟段和事实没有开放尾部。记录退出时间、退出结果、全部断言结果和对应场景的人工观察。换过目录时，对每个独立目录分别执行本节。
