# M3 人工验收手册（G）

依据 [09 M3](../design/09-milestones.md#m3-界面-v1)、[07 界面](../design/07-ui.md)、[10 国际化](../design/10-i18n.md#7-测试)、[11 截图矩阵](../design/11-design-system.md#93-检查) 和 [08 资源预算](../design/08-resources.md) 执行。每节完成后在 [测量记录](../measurements.md) 追加日期、HEAD、Windows 版本、机器配置、DPI、刷新率、供电状态、起止时间、命令、结果与待测项。记录 PID、状态和耗时，窗口标题只记录“可见/隐藏”，不复制内容。本手册准备阶段不执行桌面步骤。

## 1. 准备与独立目录

要求 Windows 桌面会话、Deno 2.9.8、仓库固定的 Rust 工具链。先从托盘退出已安装的 Quartz，确认其核心与 UI 都已结束。管道与互斥量按用户/会话固定，独立数据目录不能隔离正在运行的核心。以下命令在仓库根目录、同一 Windows PowerShell 中执行。

```powershell
Set-Location D:\Documents\403F\Quartz
git rev-parse HEAD
cargo.exe build --release -p quartz --target-dir target/windows
if ($LASTEXITCODE -ne 0) { throw 'release build failed' }
$exe = (Resolve-Path .\target\windows\release\quartz.exe).Path
$acceptanceParent = Join-Path $PWD ('target\windows\acceptance-m3-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $acceptanceParent | Out-Null
$previousLocalAppData = $env:LOCALAPPDATA
$env:LOCALAPPDATA = $acceptanceParent
$dataRoot = Join-Path $acceptanceParent 'Quartz'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
function Set-QuartzSettings([string[]]$Values) {
    & $exe settings set @Values | Out-Host
    if ($LASTEXITCODE -ne 0) { throw 'settings set failed' }
}
function Get-QuartzProcesses {
    Get-CimInstance Win32_Process -Filter "Name='quartz.exe'" | Where-Object { $_.ExecutablePath -eq $exe } | Select-Object ProcessId, ParentProcessId, CommandLine
}
```

预期：构建成功，后续数据和日志都在 `$dataRoot`。构建通常需 2–10 分钟，首次完整构建可能更长。记录 HEAD、构建结果、独立目录、系统时区与本地日期。

## 2. 实际连接与失败屏幕（约 3 分钟）

核心未运行时执行：

```powershell
$firstUi = Start-Process -FilePath $exe -ArgumentList 'ui' -PassThru
Get-QuartzProcesses | Format-Table -AutoSize
```

预期：出现“核心未运行”，有“启动核心”和“重试”。展开详细信息，复制后检查有 `error_code`，内容可读。点击“启动核心”，按钮显示启动中，连接完成后进入 Today。通过进程列表取得新的核心 PID，再执行：

```powershell
$coreInfo = Get-CimInstance Win32_Process -Filter "Name='quartz.exe'" | Where-Object { $_.ExecutablePath -eq $exe -and $_.CommandLine -notmatch '\bui\b|\bsettings\b|\bstatus\b' } | Select-Object -First 1
if (-not $coreInfo) { throw 'core PID not found' }
Stop-Process -Id $coreInfo.ProcessId -Force
if (-not $firstUi.WaitForExit(10000)) { throw 'UI stayed alive after core loss' }
$core = Start-Process -FilePath $exe -PassThru
Start-Sleep -Seconds 8
& $exe status | Out-Host
```

预期：杀核心后已连接的 UI 退出；重新启动核心能恢复服务。记录恢复按钮状态、错误码、两个 PID、断开到 UI 退出耗时和重新连接结果。八种失败屏幕的其余视觉状态在第 8 节用固定预览数据检查。

## 3. UI 生命周期（约 5 分钟）

```powershell
Set-QuartzSettings @('--resident-enabled', 'false', '--prewarm-enabled', 'false')
$deadline = (Get-Date).AddSeconds(10)
while (@(Get-QuartzProcesses | Where-Object { $_.CommandLine -match '\sui(?:\s|$)' }).Count -gt 0) {
    if ((Get-Date) -gt $deadline) { throw 'hidden UI did not exit' }
    Start-Sleep -Milliseconds 100
}
$externalUi = Start-Process -FilePath $exe -ArgumentList 'ui' -PassThru
Start-Sleep -Seconds 5
$duplicateUi = Start-Process -FilePath $exe -ArgumentList 'ui' -PassThru
if (-not $duplicateUi.WaitForExit(10000)) { throw 'duplicate UI did not exit' }
Get-QuartzProcesses | Format-Table -AutoSize
```

预期：第二次 `ui` 激活已有窗口并退出，UI PID 仍为 `$externalUi.Id`。最小化后点击托盘“打开 Quartz”，窗口恢复到前台；核心接管外部启动的 UI，不再创建第二个 UI。快速连续点击托盘十次也只有一个 UI。正常关窗后，关闭常驻的 UI 在一秒内退出。

```powershell
$normalUi = Start-Process -FilePath $exe -ArgumentList 'ui' -PassThru
Start-Sleep -Seconds 5
$errorUi = Start-Process -FilePath $exe -ArgumentList @('ui', '--core-error', 'other_session') -PassThru
Get-QuartzProcesses | Format-Table -AutoSize
```

预期：`--core-error` 可与普通 UI 同时显示独立错误窗口，关闭它不影响普通 UI；该窗口不被核心收为普通 UI。记录普通/重复/错误 UI 的 PID、重复进程退出码、激活结果、外部接管结果及关窗耗时。完成后关闭所有 UI。

## 4. Today 与真实数据（约 8 分钟，待机标注另需 18 分钟）

```powershell
Set-QuartzSettings @('--resident-enabled', 'true', '--prewarm-enabled', 'true')
$openUi = Start-Process -FilePath $exe -ArgumentList 'ui' -PassThru
& $exe status | Out-Host
```

在几个普通应用之间切换，积累至少两分钟实际活动，再通过托盘打开 Today。逐项检查并记录：

| 操作 | 预期 | 记录 |
|---|---|---|
| 日期前后移动、回今天、打开日期选择器 | 数据与所选逻辑日一致；今天的下一天与“今天”禁用；未来日期禁用；周起始日遵循核心推送的有效区域设置 | 日期、有效区域设置、按钮状态、数据刷新结果 |
| 切换日期时快速开关窗口 | 不出现上个窗口或上个日期的迟到数据 | 日期与最终数据是否对应 |
| 时间轴滚轮缩放、按钮缩放、拖动平移、全天复位 | 缩放中心与平移正确；分类主轨、应用泳道与小时柱对应；悬停显示区间信息 | 操作、响应、是否有错位或水平溢出 |
| 托盘暂停 15 分钟，再点击 Today InfoBar“恢复” | 已有数据保留；暂停显示中性 InfoBar；恢复后恢复记录 | status 的停止原因、InfoBar、恢复结果 |
| 缩到 640×480，滚动整页 | 48 像素图标栏、指标换行、图表堆叠；控件可达，正文不水平滚动 | 窗口 DIP、布局和滚动结果 |
| Windows 显示缩放 100%、150%、200%，文字大小 100%、225% | 在各档重新激活窗口后布局可用；文字大小变化重新排版，跨显示器移动没有绘图错位 | DPI、文字大小、显示器、截断与可达性 |

`persistence_failed` 的红色 InfoBar 使用第 8 节预览核对。实际存储故障恢复沿用 M1 的故障测试，避免修改本轮验收数据库。

待机标注：保持计时应已关闭；不输入至少 18 分钟（默认 3 分钟阈值后积累 15 分钟 idle），恢复后十分钟内打开 Today，检查 pending-away 行。依次用新的待机区间测试“休息”“会议”“阅读思考”“忽略”：成功后对应待处理项消失，刷新、换日后不重复。记录最后输入/恢复/选择时间、区间长度、操作和消失结果。四轮约 72 分钟，可与独立的 M2 标注验收安排在一起。

## 5. 详情侧栏（约 5 分钟）

先点击时间轴区间，再点击应用排行。区间详情有应用、起止、时长、标题可见状态、分类与规则解释；应用详情有当日/七日汇总、常见标题和分类解释。相同应用的不同窗口实例保持各自泳道。缩到 640×480 检查浮层；点击外部、按 Escape、关闭按钮均能收起；宽窗口检查并排布局。切换日期或选另一个项目时，最终详情与当前选择一致。

记录选择类型（segment/app）、数值是否与图表一致、窗口实例区分、浮层/并排切换与三种关闭方式。标题与应用路径的具体内容不抄入报告。

## 6. 常驻与预热（约 8 分钟，电池测试按设备条件安排）

```powershell
& $exe settings get | Out-Host
Set-QuartzSettings @('--resident-enabled', 'true', '--prewarm-enabled', 'true', '--prewarm-on-battery', 'false')
Get-QuartzProcesses | Format-Table -AutoSize
```

预期：默认常驻开启，核心启动后创建没有窗口的 UI。记录 Hidden 的 UI PID；打开、关窗、再打开二十次，窗口销毁但 PID 保持。第 9 节自动记录这二十轮。切到常驻关闭时，隐藏 UI 退出；可见 UI 保持显示，随后关窗一秒内退出；再开启常驻会创建 Hidden UI。

崩溃重启：从进程列表确定 Hidden UI 的 PID，执行 `Stop-Process -Id <UI-PID> -Force`，记录崩溃时刻；核心安排 60 秒冷却后重建 UI，期间重复点击不生成多个进程。重新记录新 PID、重建时刻。随后从托盘“退出 Quartz”，等待至少 65 秒，确认核心和 UI 均不重启；再执行 `$core = Start-Process -FilePath $exe -PassThru` 继续。

```powershell
Set-QuartzSettings @('--resident-enabled', 'false', '--prewarm-enabled', 'true', '--prewarm-on-battery', 'false')
```

把鼠标移到托盘图标上手动悬停：创建无窗口预热 UI；从认证 hello 起 8 秒未打开则退出，从上次成功预热启动起 60 秒内不重复预热。分别在冷却过后测试刚悬停就点击、预热完成后点击、约第 8 秒点击：最终均只有一个可见窗口，首帧后“正在打开…”反馈清除，预热超时不能关闭已打开窗口。每次用新一轮冷却测试，记录悬停/点击/退出时刻、PID 和对应 `click_to_first_frame_ms`。鼠标悬停由人工完成，自动测量只从 Hidden 或完全关闭状态发送托盘点击。

拔掉电源，默认 `prewarm-on-battery=false` 时悬停不创建 UI；打开该设置后再次等待冷却并悬停，允许预热。重新插电，恢复默认。记录供电状态、设置值、冷却起点、是否创建 UI 与 TTL；常驻开启时不走悬停预热规则。

## 7. 运行中切换语言与区域设置（约 3 分钟）

先从托盘暂停记录，等待当前查询完成，使本节比较期间的数据保持稳定。保持 UI 打开在 Today，选中一个区间或应用以打开详情侧栏，再打开日期选择器。记录当前 UI PID、所选日期、详情对象和查询数值。以下三条语言命令逐条执行，每条返回后立即检查界面，再执行下一条：

```powershell
& $exe settings set --language en | Out-Host
if ($LASTEXITCODE -ne 0) { throw 'English language update failed' }
```

```powershell
& $exe settings set --language zh-CN | Out-Host
if ($LASTEXITCODE -ne 0) { throw 'Chinese language update failed' }
```

```powershell
& $exe settings set --language auto | Out-Host
if ($LASTEXITCODE -ne 0) { throw 'automatic language update failed' }
```

预期：核心提交设置后立即切换托盘菜单和提示，通过 `state` 推送新语言；Today、详情侧栏、日期按钮与日期选择器文字、gpui-component 组件文字在下一帧切换。菜单已打开时关闭后重新展开，托盘提示重新悬停读取；`auto` 恢复核心启动时检测到的系统首选语言。UI PID、所选日期、详情对象和查询数值保持不变；时长等数值的显示格式可随语言变化。用 `Get-QuartzProcesses | Format-Table -AutoSize` 核对 PID，用 `& $exe settings get | Out-Host` 核对存储偏好与有效语言。

区域设置可独立修改，逐条检查时间文本与日历周起始日，再恢复自动设置：

```powershell
& $exe settings set --hour-cycle h12 --first-day-of-week sunday | Out-Host
if ($LASTEXITCODE -ne 0) { throw '12-hour/Sunday update failed' }
& $exe settings set --hour-cycle h24 --first-day-of-week monday | Out-Host
if ($LASTEXITCODE -ne 0) { throw '24-hour/Monday update failed' }
& $exe settings set --hour-cycle auto --first-day-of-week auto | Out-Host
if ($LASTEXITCODE -ne 0) { throw 'automatic regional settings update failed' }
```

记录每次命令、存储偏好与有效设置、UI PID、托盘/页面/详情/日期/组件文字变化、周起始日、查询数值一致性和切换结果。en-XA 的长译文布局由第 8 节三套截图中的调试伪语言组验证，预览使用 `QUARTZ_PREVIEW_LANG=en-XA`。完成后通过 Today 的 InfoBar“恢复”继续记录。

## 8. 截图生成与评审（约 30–60 分钟）

可在 Quartz 退出后执行，预览只读固定数据，不连接核心。先构建调试预览以包含 en-XA，然后执行脚本：

```powershell
cargo.exe build -p quartz-ui --example preview --features preview --target-dir target/windows
if ($LASTEXITCODE -ne 0) { throw 'preview build failed' }
deno task preview-screenshots --mica-wallpaper=reference
if ($LASTEXITCODE -ne 0) { throw 'screenshot capture failed' }
Invoke-Item .\target\m3-screenshots\index.md
```

脚本每次只启动自己的 preview.exe，按 PID 捕获并关闭；超时则终止该预览。最后一张激活预览以捕获实际 Mica，并临时使用蓝色参考壁纸，结束时恢复原壁纸；需要保留当前壁纸时使用 `--mica-wallpaper=current`。其余截图在屏外完成。

输出为 `target/m3-screenshots/<lang>/<scenario>-<variant>.png`，包含 `index.md` 与 `observations.json`。语言为 zh-CN / en / en-XA；每个场景有 light、dark、fallback-light、fallback-dark、high-contrast 五种外观。主窗口 1280×800；Today 与 migration-failed 另有 640×480 组。场景覆盖加载完成、loading、empty-today、empty-past、stopped-paused、stopped-persistence-failed、query-failed、date-picker、today-nav、segment/app 详情和批准错误稿全部八态；默认收起的四种错误另提供展开详情组。每种语言 125 张，zh-CN 另有一张真实 Mica 对照，共 376 张。

按 [07 第 11 节](../design/07-ui.md#11-截图评审) 将三套截图交用户评审。逐张记录：布局层级与批准稿一致；长译文不遮挡按钮；图表、规则解释与详情可读；停止原因颜色正确；错误操作、展开详情与长备份命令可达；最小尺寸无横向溢出；Mica 回退不透明；高对比度焦点与状态可分辨；`observations.json` 中每次关闭成功、实际 Mica 的 backdrop 和 active 值合理。自动捕获完成后仍需用户逐张视觉确认。

## 9. 资源与首帧测量（驻留约 18–22 分钟，按需约 15–19 分钟）

先从托盘退出所有 Quartz。测量脚本拒绝已有核心或同路径进程，自动在输出目录的 `data` 子目录设置独立 `LOCALAPPDATA` 并在结束时还原；不复用上述交互验收数据。保持显示器亮屏、不锁屏、不输入，不连接浏览器扩展，供电与刷新率保持不变。

```powershell
deno task measure --Exe $exe --mode resident --SettleSeconds 30 --IdleSeconds 600 --segments 3 --opens 20
if ($LASTEXITCODE -ne 0) { throw 'resident measurement failed' }
deno task measure --Exe $exe --mode on-demand --SettleSeconds 30 --IdleSeconds 600 --segments 3 --opens 20
if ($LASTEXITCODE -ne 0) { throw 'on-demand measurement failed' }
```

只重测核心时：

```powershell
deno task measure --Exe $exe --mode core-only --SettleSeconds 30 --IdleSeconds 600
if ($LASTEXITCODE -ne 0) { throw 'core measurement failed' }
```

预期：core-only 通过 `quartz settings set` 关闭常驻和预热，稳定后十分钟采样；resident 随后分别测 hidden-never-opened、hidden-after-close（与此前相同 UI PID）、visible-static，每个状态稳定后测三个 30 秒段。每秒记录核心与 UI 的 Private Bytes、Private WS、线程、句柄；报告各段 CPU 增量、内存等指标的中位数/最大值，并汇总同场景各段 CPU 的中位数与最大值。按需模式保留 core-only、visible-static，关闭窗口断言一秒内进程退出。两种完整模式都有二十轮开关，记录每轮 UI PID、UI Private Bytes（驻留取关窗后，按需取退出前）、核心快照；驻留模式强制 PID 不变。额外 N 次打开取每次新写入 core.log 的首帧确认，输出 nearest-rank P50/P95/最大值；驻留从 Hidden 打开，按需从无 UI 打开。测量用托盘点击消息作为计时触发点。可用 `--opens N`、`--segments N`、`--output <目录>`；原 `--Exe`、`--SettleSeconds`、`--IdleSeconds`、`--ScreenshotPath` 仍可用。手动预热首帧按第 6 节记录。

输出目录默认为 `target/windows/measure-<mode>-<timestamp>`，含 `report.md`、`report.json`、逐秒与逐轮数据 `samples.json` 和隔离日志。失败时也保存已完成的采样。报告模块检查及二进制字节数；不加载核心 NVIDIA 用户态模块。

| 项目 | 预算/判读 |
|---|---|
| 核心 Private Bytes / Private WS | 目标 8–12 / ≤12 MiB，上限均为 16 MiB |
| 核心线程与十分钟 CPU | 目标 ≤8 线程、≤150 ms；上限 12、300 ms |
| 二十轮核心 Private Bytes 增量 | 目标 ≤1 MiB，上限 2 MiB；检查每轮趋势及线程/句柄是否持续增长 |
| 可见与隐藏 UI Private Bytes | ≤100 MiB |
| 可见静态与隐藏 UI CPU | 每个 30 秒段 ≤20 ms，报告中位数与最大值 |
| 首帧 | 当前机器冷启动 ≤4.5 s、热启动 ≤0.8 s；Hidden 或预热点击到首帧 P50 ≤1 s，同时记录 P95 |
| 按需关窗 | 一秒内 UI 退出 |
| 核心 GPU 与唤醒 | 无 `nv*.dll`；ETW 定时唤醒目标 ≤0.1 次/秒、上限 0.25 次/秒 |

[2026-11-22 M3-E/F 记录](../measurements.md#2026-11-22-m3-ef常驻界面实测与空闲唤醒调查) 已接受隐藏 UI 的 CPU 与内存偏差、保留可见静态 UI CPU 偏差，功能完整后优化。已有样本 Hidden 为 109.4 MiB、78 ms/30 s，可见静态为 781 ms/30 s，Hidden 首帧 106 ms；本轮仍按原预算列结果。此前核心 140 ms/30 s 样本未保证无输入，十分钟核心空闲重新采样。脚本检查生命周期、采样、首帧记录完整性及二十轮核心增量上限；预算是否通过由上述表与实测报告核对。

定时唤醒和拖动帧率由 WPR/WPA 另外观察，沿用 [08 测量方法](../design/08-resources.md#2-测量方法)：使用 CPU 与 Generic Events profile 录制十分钟空闲，统计核心线程定时唤醒；拖动时间轴时检查 ≥60 fps。记录采样起止、每段数值、二十轮趋势、P50/P95、实际首帧样本数、模块结果、预算判读与接受偏差。

## 10. 收尾

从托盘退出本轮交互验收核心，确认 UI 一起结束，再还原 PowerShell 环境：

